# Discord運用コマンドとダッシュボード

管理画面は `/discord_bot_admin.html`。既存Firebase認証・指定管理者3名のサーバー側確認を使う。Discordの実行権限とWeb管理権限は別。

## 確認コマンド

- `/ubuntu status`：Ubuntuの現在値・警告・データ時刻。
- `/ubuntu services`：Docker・PM2・連携API。
- `/ubuntu report`：収集済みデータで定時報を表示。通常の定時送信枠は消費しない。
- `/ubuntu logs target:…`：許可済みサービスの最近40行。任意パス・任意shellは受け付けない。表示量の上限あり。
- `/ubuntu events`：最近15件の障害・復旧。
- `/ubuntu github view:… repository:… page:…`：基本情報、5コミット、Actions失敗箇所、公開の差、PR、Issue、接続状態。PR・Issueは10件ずつページ指定。
- `/ubuntu help`：使い方。

実行ロールの初期値は1489628881135730852・1489628881135730851・1489628881135730850。結果は実行チャンネルで公開し、本文中のメンションは無効化する。既定チャンネルは既存のUbuntu通知先。実行不可の説明は本人だけに表示する。

各コマンドで有効・無効、ロール／ユーザー、チャンネル、クールダウンを指定可能。ロールかユーザーを個別指定すると共通の利用者指定を置換する。空欄は共通設定。全体同時実行は3件まで。

## 既存Botとの統合

`discord-bot/ubuntu_admin.js` を既存Botの `functions/ubuntu_admin.js` へ配置する。`bot-status-integration.patch` は既存21コマンドの定義を変えず、登録一覧に新しい `/ubuntu` 1件を足す最小差分。既存 `/status`、`/github`、その他の動作は変更しない。新機能だけでは再起動等の操作は実行できない。

## 設定・履歴・秘密情報

設定は監視データフォルダの `discord-command-config.json`（本人のみ読取）。Botはコマンド実行ごとに読み直し、30秒ごとのheartbeatに読込revisionを記録する。保存には最新revisionと明示確認が必要。他の管理者の更新を上書きしない。設定にトークン本体は含めない。

GitHubは既定で公開APIを使用。明示的に用意された `TAYUNET_GITHUB_TOKEN` があれば利用するが、この実装で秘密値の移送や発行はしない。認証状態・期限・scopeはAPIが返す範囲だけ表示し、不明なものは未確認とする。画面に出すのは設定されたGitHubトークンの末尾4文字まで。

結果・履歴の文字列はエスケープし、ログの秘密値・生トークン・秘密鍵・端末制御文字を除去する。動的DOM描画は `bot-dom.js` の1箇所に集約し、inertなtemplateをタグ／属性の許可リストで洗浄してから挿入する。イベント属性・URL属性・script・iframe・foreignObject等は許可しない。XSS sink基準はこの監査対象1箇所だけを追加（605→606）。ページ内の16箇所に分散した直接代入は残さない。

## 通知

Ubuntu運用通知と追加GitHub通知は、種類ごとに送信先と異常時ロールを設定できる。失敗だけメンションし、成功・復旧・起動・PR・Issue・定時報・テストはメンションしない。初期値の異常時ロールは1489628881135730852だけ。

追加のActions失敗・公開成功・PR・Issue通知は初期状態で無効。既存PR Webhook機能と重複しないよう、必要なものだけ有効にする。GitHub確認は5分間隔、通常取得は5分キャッシュ。初回は基準登録のみ。取得失敗を正常扱いしない。1回の取得量は制限し、通知確認の間に大量の変更があった場合は全件の保証をしない。

通知一時停止では送信待ちを保持し、GitHub通知の確認も休止する。停止中も管理者のテスト送信だけは1件送れる。独立したGitHub Actions外形監視と既存の汎用Bot機能は、この設定画面の管理対象外で動作を維持する。

## 稼働情報の限界

OS再起動はkernel boot_idで検知。初回は基準登録、同じ起動IDの監視再起動で誤通知しない。最初の収集成功後に起動情報を通知する。実機再起動を行わない限り、実際の電源断からの全経路は未検証。

再起動理由は管理画面の操作記録と照合できる場合だけ確定表示。PM2の再起動回数や終了コードだけから手動・クラッシュと断定しない。ログサイズは参照可能な固定パスだけを確認。未取得は0と表示しない。
