# 障害・復旧通知

Ubuntuの異常と外部サービスの状態変化は、監視DBのイベント・送信待ちへ同時に保存する。外部サービスの観測状態は保存成功後だけ進める。Discordへ送れない間に障害が復旧しても、障害と復旧の両方を保持する。

- 送信待ちは順番に送り、成功したものだけ削除する。失敗時は60秒から最大30分間隔で再試行する。再起動でも残る。
- 通知には送信時刻とは別に記録時刻をJSTで付ける。公式障害の実際の発生時刻とは区別する。
- 異常だけロール1489628881135730852をメンションする。復旧・保守情報・定時報はメンションしない。
- 正常な初回観測は通知しない。外部サービスの公式発表は、本システムへの影響が確認できたという意味ではない。
- 外部状態の保存直前にプロセスが停止した場合や、Discord側が受領した直後に通信が切れた場合は通知が重複する可能性がある。未送信の記録を失うことを避ける方式。
- 定時報はJST9/10/12/16/17/20時。成功した枠を記録し重複を抑止し、枠の開始5分以内に再試行する。期間外の古い定時報は新たに生成しない。

サーバー停止はGitHub側の外形監視でも確認する。ただし実行間隔の遅れがあり、Discord自体の停止中は即時配信できない。監視で一度も観測できなかった短い外部障害の履歴まで保証するものではない。
